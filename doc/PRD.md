# PRD: Воркшоп "Правила, команди та навички для Агентних IDE"

**Версія**: 1.0  
**Дата**: 2026-01-14  
**Статус**: В розробці

---

## 1. Огляд продукту

### 1.1 Мета документа

Цей Product Requirements Document (PRD) описує вимоги до інтерактивного воркшопу на тему "Правила, команди та навички для Агентних IDE", призначеного для навчання розробників ефективній роботі з агентними інтегрованими середовищами розробки.

### 1.2 Контекст

Проект створюється для події FWDays 2026 та має на меті навчити учасників:
- Ефективно використовувати Агентні IDE для повсякденної роботи
- Розуміти основні принципи та правила роботи з помічниками ШІ
- Застосовувати найкращі практики та уникати типових помилок

### 1.3 Цільова аудиторія

**Основна аудиторія:**
- Розробники різних рівнів (junior, middle, senior)
- Team leads та tech leads
- DevOps інженери
- QA інженери, які працюють з кодом

**Рівень знань:**
- Базове розуміння програмування
- Досвід роботи з IDE (VS Code, IntelliJ, тощо)
- Зацікавленість у використанні інструментів ШІ

**Розмір аудиторії:**
- 20-50 учасників на сесію
- Можливість проведення кількох сесій

## 2. Цілі та метрики успіху

### 2.1 Бізнес-цілі

1. **Навчання**: Навчити учасників ефективній роботі з Агентними IDE
2. **Підвищення продуктивності**: Допомогти розробникам збільшити продуктивність на 30-50%
3. **Розповсюдження знань**: Поширити найкращі практики роботи з помічниками ШІ
4. **Брендинг**: Позиціонувати FWDays як джерело актуальних знань про інструменти ШІ

### 2.2 Метрики успіху

**Кількісні метрики:**
- Кількість учасників: мінімум 20 на сесію
- Рейтинг задоволеності: мінімум 4.5/5.0
- Відсоток учасників, які застосували знання: мінімум 70%
- Кількість запитань під час сесії: 5-10

**Якісні метрики:**
- Учасники розуміють основні правила роботи з Агентними IDE
- Учасники можуть застосувати отримані знання в реальних проектах
- Позитивні відгуки про практичність матеріалів

## 3. Формат та структура воркшопу

### 3.1 Формат

**Тип**: Інтерактивний воркшоп з презентацією та практичними вправами

**Тривалість**: 60-90 хвилин

**Структура:**
1. **Вступ** (5 хв) - знайомство, цілі воркшопу
2. **Теоретична частина** (30-40 хв) - презентація з інтерактивними елементами
3. **Практична частина** (20-30 хв) - вправи та демонстрації
4. **Q&A та висновки** (10-15 хв) - відповіді на запитання, підсумки

**Поточна структура (13 слайдів):**

5. Основні команди та інструменти
6. Навички для ефективної роботи
7. Найкращі практики (Планування та Ітерації)
8. Найкращі практики (Безпека та Навчання)
9. Приклади ефективних команд
10. Типові помилки та як їх уникнути
11. Інструменти для перевірки якості
12. Висновки
13. Дякую за увагу!

**Рекомендована структура для воркшопу (15-18 слайдів):**

1. Титульний слайд + план воркшопу
2. Знайомство з аудиторією (інтерактивний опитувальник)
3. Що таке Agentic IDE?
4. Основні правила роботи (Правило №1-2)
5. Правила роботи (Правило №3-4)
6. **Практична вправа 1**: Формулювання завдань для ШІ
7. Основні команди та інструменти
8. **Демонстрація**: Робота з реальними командами
9. Навички для ефективної роботи
10. Найкращі практики (Планування та Ітерації)
11. Найкращі практики (Безпека та Навчання)
12. **Практична вправа 2**: Аналіз та покращення команд
13. Приклади ефективних команд
14. Типові помилки та як їх уникнути

## 4. Функціональні вимоги

### 4.1 Презентація

**FR-1: Базова презентація**
- Презентація має бути доступна через Slidev
- Підтримка навігації клавіатурою та мишею
- Можливість експорту в PDF для роздачі матеріалів
- Адаптивний дизайн для різних розмірів екранів

**FR-2: Інтерактивні елементи**
- Анімації появи контенту (v-clicks)
- Діаграми Mermaid для візуалізації процесів
- Інтерактивні опитувальники (опціонально)
- Демонстрації в реальному часі

**FR-3: Мультимедіа**
- Підтримка зображень та скріншотів
- Відео демонстрації (опціонально)
- Приклади коду з підсвіткою синтаксису

### 4.2 Практичні вправи

**FR-4: Вправа 1 - Формулювання завдань**
- Учасники отримують завдання переформулювати поганий приклад команди
- Порівняння результатів з хорошим прикладом
- Обговорення в парах або малих групах

**FR-5: Вправа 2 - Аналіз команд**
- Аналіз реальних прикладів команд
- Визначення проблем та покращень
- Створення покращених версій

**FR-6: Демонстрації**
- Живі демонстрації роботи з Agentic IDE
- Показ реальних сценаріїв використання
- Інтерактивна взаємодія з аудиторією

### 4.3 Матеріали для учасників

**FR-7: Роздавальні матеріали**
- PDF версія презентації
- Чек-лист основних правил
- Шпаргалка з командами та інструментами
- Посилання на додаткові ресурси

**FR-8: Додаткові ресурси**
- Посилання на документацію
- Приклади коду
- Відео-туторіали (опціонально)
- GitHub репозиторій з матеріалами

## 5. Технічні вимоги

### 5.1 Платформа презентації

**TR-1: Slidev**
- Версія: 0.49.0 або вище
- Node.js: 18.0.0 або вище (обов'язково)
- npm: версія, сумісна з Node.js 18+

**TR-2: Альтернативний формат**
- HTML версія презентації для перегляду без Node.js
- Підтримка всіх основних браузерів (Chrome, Firefox, Safari, Edge)

### 5.2 Інфраструктура

**TR-3: Для презентера**
- Ноутбук з Node.js 18+ встановленим
- Стабільне інтернет-з'єднання
- Проектор або великий екран
- Резервна копія презентації (PDF)

**TR-4: Для учасників**
- Доступ до інтернету (для практичних вправ)
- Можливість відкрити HTML версію презентації
- Опціонально: власні ноутбуки для практичних вправ

### 5.3 Продуктивність

**TR-5: Швидкість завантаження**
- Презентація має завантажуватися за < 3 секунди
- Плавні переходи між слайдами
- Швидка реакція на навігацію

**TR-6: Сумісність**
- Працює на Windows, macOS, Linux
- Підтримка різних розмірів екранів (від 1024x768 до 4K)

### 7.1 Якість контенту

**CR-1: Актуальність**
- Всі приклади мають бути актуальними
- Використання сучасних інструментів та практик

**CR-2: Практичність**
- Всі приклади мають бути практичними та застосовуваними
- Реальні сценарії використання
- Конкретні команди та інструменти

**CR-3: Зрозумілість**
- Матеріал має бути зрозумілим для різних рівнів знань
- Пояснення термінів та концепцій

### 7.2 Структура контенту

**CR-4: Логічна послідовність**
- Від простого до складного
- Кожен слайд має логічне продовження попереднього
